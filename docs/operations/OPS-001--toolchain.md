# OPS-001 · 개발 도구와 검증

사전 조건: mise 설치. 루트에서 `mise trust`, `mise install`, `mise run setup`을 실행한다. 도구 버전은 mise.toml, Node 패키지는 pnpm-lock.yaml로 고정한다. 설치 후 Lefthook 연결을 확인한다. npm 잠금 파일을 함께 만들지 않는다.

## 개발과 배포

`mise run dev`는 학습 화면용 Vite 서버다. 로컬 호출 기록·검토 API가 필요하면 별도 터미널에서 `mise run hub`를 실행한다. Vite는 `/api`를 허브로 전달한다. 검토 CLI의 독립 패키징은 기존 prepack 계약을 유지한다.

`mise run build` 결과인 dist만 정적 호스트에 배포한다. 하위 경로 배포는 Vite의 `--base`로 지정한다. HTML의 module script는 빌드하고, classic script와 순서 의존 자산은 원본으로 보존한다. 공개 자산 목록 밖의 개발 도구·시험 자료·로컬 기록은 포함하지 않는다.

## 품질과 비밀정보

`mise run check`는 린트·포맷·미사용 코드·빠른 계약 검증이다. `mise run test`는 빌드 후 전체 브라우저·패키징 검증이다. `mise run secrets`는 전체 Git 이력을 검사한다. 실제 명령 정의는 package.json이 소유한다.

커밋은 실제 인덱스 내용의 비밀정보·Biome 검사, 푸시는 전송할 커밋의 비밀정보·빠른 검증을 실행한다. 부분 스테이징에서 작업 트리의 다른 내용으로 검사를 대체하거나 자동 재스테이징하지 않는다. 로컬 hook 우회를 보완하기 위해 CI에서 같은 기준과 전체 e2e를 실행한다.

검출 시 값 자체를 출력·공유하지 않는다. 실제 자격증명이 노출됐다면 먼저 발급처에서 폐기·재발급하고 이력 정리는 별도로 판단한다. 테스트 데이터 예외는 구체적 경로·규칙으로 제한하며 전체 보안 규칙을 끄지 않는다.

## 범위와 복구

Biome은 자사 JS·CSS·설정 파일을 검사한다. HTML 공백 포맷은 현재 템플릿 계약을 보존하며 보류한다. classic 핸들러와 브라우저 평가 함수의 외부 바인딩만 명시하고, 관련 동작은 실제 브라우저로 검증한다. Knip은 HTML에서 script 진입점을 읽으며 호환 export의 예외는 설정 가까이에 이유를 기록한다.

설치 불일치는 루트에서 고정 잠금 파일로 다시 설치한다. 실패한 검사는 원인을 수정한 뒤 같은 명령을 재실행한다. 원격 필수 검사 이름은 CI 작업과 일치시켜야 하며, 로컬 설정 파일만으로 GitHub 브랜치 보호가 활성화되지는 않는다.
